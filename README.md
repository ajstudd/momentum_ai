# Solo Leveling (Momentum AI)

My personal gamified self-improvement web application that transforms everyday goals into an RPG-style adventure. Inspired by the Solo Leveling series, I built this to turn my personal development journey into an engaging game where I track five core stats (Strength, Vitality, Agility, Intelligence, Perception), complete AI-generated daily quests, gain XP, unlock badges and titles, and watch my character sheet level up as I improve in real life.

**🚀 Live Demo:** [https://arise.junaid.co.in/](https://arise.junaid.co.in/)

## What This Project Does

This is my digital companion for self-improvement. The app uses Google's Gemini AI to generate personalized daily quests based on my current stats, goals, and history. Every quest I complete awards XP and stat gains, creating a feedback loop that keeps me motivated. The system maintains detailed logs of my progress, caches quest data for instant loading, and adapts to my growth over time.

> This project is inspired by Solo Leveling (anime/manga) but is a standalone personal development tool with no copyrighted assets.

## Key Features I Built

- **RPG-Style Character System**: Five upgradable stats that represent different aspects of personal growth

- **Secure Authentication**: JWT-based auth protecting all my personal data

## How I Architected It

I designed this app with clean separation of concerns and performance in mind:

- **API Routes** (`app/api/*`): Handle authentication, profile management, stats updates, setup flow, and quest lifecycle
- **Authentication Flow**: JWTs issued on register/login, stored client-side. I created a custom `useAuthenticatedFetch` hook that handles token injection and automatic redirect on 401s
- **Data Layer**: Mongoose models for users, setup responses, quest cache, badges, passives, titles, and logs
- **AI Integration** (`lib/gemini.ts`): Constructs context-rich prompts from my stats, profile, focus logs, and quest history. Parses structured JSON responses for questlines, passives, metrics, and title unlocks
- **Performance Strategy**: Quest results cached per user with 24-hour freshness window. API routes use selective field queries for fast response times

## Data Models

### User Model (`lib/models/User.ts`)

The core of my personal data:

- Authentication: email (unique), hashed password
- Progress tracking: setupCompleted flag, xp, level
- Stats: strength, vitality, agility, intelligence, perception
- History: logs (stat changes), completedQuests, focusLogs
- Profile: structured profile data used by Gemini for personalization
- Rewards: badges, passives, titles
- Cache: questCache with 24h freshness tracking

### SetupResponse Model (`lib/models/SetupResponse.ts`)

Initial assessment data:

- Links to userId
- Stores responses for each stat question
- Timestamps for tracking setup completion

## API Endpoints I Created

### Authentication

- `POST /api/auth/register` - Create account, returns JWT
- `POST /api/auth/login` - Login, returns JWT
- `GET /api/auth/me` - Get current user data
- `POST /api/auth/logout` - Logout handler

### Setup & Onboarding

- `GET /api/setup` - Get setup questions
- `POST /api/setup` - Submit responses, AI analyzes and assigns initial stats

### Profile & Stats Management

- `GET /api/profile` - Fetch profile, badges, xp/level, passives, titles
- `POST /api/profile` - Update profile (invalidates quest cache for re-personalization)
- `GET /api/stats` - Get current stats and history logs
- `PATCH /api/stats` - Update stats (internal)

### Quest System

- `GET /api/quests` - Generate or retrieve cached daily quests
- `POST /api/quests/complete` - Submit quest completion with proof, awards XP and stat gains
- `GET /api/quests/completed` - View quest history
- `POST /api/focus` - Record stat focus for current quest
- `POST /api/quest-logs` - Log quest progress (internal)

### Rewards & Progression

- `GET /api/badges` - View earned badges
- `GET/POST /api/milestones` - Track milestone achievements

### Development Utilities

- `POST /api/reset-setup` - Reset setup state for testing

All protected endpoints require JWT Bearer token in Authorization header.

## Running the Project

### Prerequisites

- Node.js 18+
- MongoDB (I use MongoDB Atlas)
- Google Gemini API key

### Setup Steps

1. **Install dependencies**

   ```bash
   npm install
   ```

2. **Configure environment variables**

   ```bash
   copy .env.example .env.local
   ```

3. **Add required environment variables to `.env.local`**

   - `MONGODB_URI` - MongoDB connection string
   - `JWT_SECRET` - Secret for signing JWTs
   - `GEMINI_API_KEY` - Google Generative Language API key

4. **Start development server**

   ```bash
   npm run dev
   ```

   App runs at http://localhost:3000

### Available Scripts

- `npm run dev` - Start Next.js dev server with Turbopack
- `npm run build` - Create production build
- `npm run start` - Run production server
- `npm run lint` - Run ESLint checks

## My User Journey

1. **Onboarding**: Create an account and complete the setup assessment. Gemini AI analyzes my responses to assign personalized starting stats.

2. **Daily Quest Generation**: Each day, I fetch new quests tailored to my current stats, profile, and completion history. The system caches these for 24 hours to keep things fast.

3. **Quest Completion**: I choose a quest (optionally marking which stat I want to focus on), work on it in real life, then submit proof of completion.

4. **Progression**: The system awards XP, stat gains, badges, and sometimes unlocks new passive abilities or titles.

5. **Tracking Growth**: I can review my progress through the profile and stats pages, seeing how far I've come.

## Technical Decisions & Optimizations

**Performance**

- Implemented quest caching strategy to minimize Gemini API calls and reduce latency
- API routes use selective field queries for faster responses
- MongoDB indexes on email for quick user lookups

**Security**

- All protected routes verify JWT tokens
- 401 responses automatically clear tokens and redirect to login
- Sensitive data stored only in environment variables, never in code

**Scalability Considerations**

- Current architecture supports multiple users
- Could add compound indexes on `completedQuests.completedAt`, `milestones.badge`, or `setupresponses.userId` as data grows
